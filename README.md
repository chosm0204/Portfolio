# Portfolio

문제 정의부터 AI 구조 설계, 프론트엔드 구현, 결과 검증까지 정리한 개인 포트폴리오 웹사이트입니다.

**조승민** · 프론트엔드 · AI

---

## 왜 이렇게 만들었나

만든 것보다 **판단을 남기는 데** 무게를 뒀습니다. 아래는 이 저장소에서 내린 결정과 그 이유입니다.

### 콘텐츠를 코드에서 분리했다

모든 카피가 `content/` 아래 타입이 붙은 데이터로 있습니다. 컴포넌트에는 문장이 한 줄도 없습니다.

```ts
// types/case.ts — 케이스 본문 블록의 판별 유니온
type CaseBlock =
  | { kind: "lead"; ... }
  | { kind: "note"; ... }
  | { kind: "table"; ... }
  | { kind: "metrics"; ... }
```

문장을 고칠 때 JSX를 열지 않아도 되고, 나중에 영문판을 붙일 때 데이터만 갈아 끼우면 됩니다.
강조 구간은 문자열에 HTML을 섞는 대신 `{ text, strong }` 조각으로 표현해, 마크업이 데이터에 새어 들어오지 않게 했습니다.

### Tailwind 대신 CSS 변수 + CSS Modules

디자인 토큰이 이미 CSS 변수로 정의돼 있었고, 색 사용처에 **규칙**이 있었습니다.

> 포인트 색은 '의미'에만 쓴다. 강조·선택·현재 위치·측정값을 나를 때만.
> 이 색을 회색으로 바꿔서 독자가 무언가를 놓치지 않는다면, 그건 장식이다.

유틸리티 클래스로는 이 규칙을 지키기 어렵습니다. 어디에 어떤 색이 쓰였는지 추적이 안 되니까요.
CSS 변수로 두면 `grep`으로 검사할 수 있고, 다이어그램 SVG까지 같은 토큰을 씁니다.

### 다이어그램을 이미지가 아니라 인라인 SVG로

| 이유 | |
|---|---|
| PDF 변환 | 벡터라 확대해도 깨지지 않는다 (웹 → PDF 출력이 전제) |
| 반응형 | 모바일에서 글자가 흐려지지 않는다 |
| 토큰 연동 | 포인트 색을 바꾸면 다이어그램도 따라온다 |
| 접근성·검색 | SVG 내 텍스트를 스크린리더가 읽고 검색에도 걸린다 |
| 수정 비용 | 수치가 바뀌면 코드 한 줄 |

이미지 파일을 쓰는 곳은 실제 화면 스크린샷과 현장 사진 둘뿐입니다.

### 모션은 네 개만

효과를 넣을 때마다 하나를 물었습니다. **이게 없으면 사용자가 뭘 놓치는가?**

| 어디 | 무엇 | 왜 |
|---|---|---|
| 카드 → 케이스 | 제목이 이어지는 전환 | 어디로 왔는지 설명 |
| 지표 진입 | 막대 차오름 + 숫자 카운트업 (한 번만) | 압축 폭을 감각으로 전달 |
| 목차 | 현재 섹션 표시 | 긴 문서에서 위치 파악 |
| 링크·버튼 | 호버·포커스 반응 | 누를 수 있다는 신호 |

답이 없는 효과는 넣지 않았습니다. 섹션 페이드인, 패럴랙스, 프리로더가 그래서 빠졌습니다.
`prefers-reduced-motion`을 켠 환경에서는 전부 즉시 완성 상태로 보입니다.

### 전화번호를 정적 HTML에 남기지 않았다

연락처는 열어두되 봇이 긁어가지 않게 두 겹으로 막았습니다.

- `tel:` href를 렌더 결과가 아니라 마운트 후 DOM에 붙입니다 → 정적 HTML·RSC 페이로드 어디에도 `tel:`이 없습니다
- 번호가 연속 문자열로 존재하지 않고, 조각과 하이픈이 각각 다른 요소입니다

사용자에게는 똑같이 보이고 똑같이 눌립니다. 다만 JS가 꺼진 환경에서는 표시만 되고 통화 연결은 되지 않습니다 — 스크래핑 방지와의 맞교환입니다.

## 품질 기준

측정 가능한 값으로만 잡았습니다.

| 항목 | 기준 | 현재 |
|---|---|---|
| 본문 조판 | 17px / line-height 1.7 / `word-break: keep-all` | 충족 |
| 명도 대비 | 4.5:1 이상 | 보조 텍스트 5.03:1 · 포인트 7.07:1 · 배지 6.40:1 |
| 렌더링 | 본문이 view-source에 보일 것 | 전 페이지 정적 프리렌더 |
| 반응형 | 375px에서 가로 스크롤 없음 | 충족 |
| 키보드 | 전 페이지 이동 가능, 포커스 표시 명확 | `:focus-visible` |
| 인쇄 | 웹 → PDF 출력 시 레이아웃 유지 | `@media print` 대응 |

**본문이 정적 HTML에 있어야 한다**는 기준을 특히 신경 썼습니다.
국내 개인 포트폴리오를 조사하면서, 클라이언트 렌더링으로 배포해 검색·링크 미리보기가 전혀 잡히지 않는 사례를 여럿 봤습니다.

한글 조판에서는 `word-break: keep-all`이 필수입니다. 없으면 단어 중간에서 줄이 바뀝니다.

## 검증되지 않은 주장을 막는 장치

이 저장소에는 **콘텐츠 게이트**가 있습니다.

포트폴리오에서 제일 위험한 건 깨진 레이아웃이 아니라 **근거 없는 문장**입니다.
발표 자료에 남아 있던 수치를 무심코 옮겨 적으면, 면접에서 "그 근거가 뭐죠?"라는 질문에 무너집니다.
그래서 규칙을 문서로만 적지 않고 빌드에 걸었습니다.

```bash
npm run check     # 단독 실행
npm run build     # 검사를 통과해야 빌드된다
```

검사 항목은 네 가지입니다.

| | 무엇을 막나 |
|---|---|
| 과장 어휘 | "전문가" · "혁신적" · "독창적" — 근거 없이 쓰지 않는다 |
| 확정 수치 | `FACTS.md`에 등록된 값과 대조. 폐기된 옛 수치가 들어오면 차단 |
| 자격증명 | 하드코딩된 API 키·토큰 |
| 개인정보 | 평문 전화번호, 학교가 식별되는 고유명사, 제3자 실명 |

[`FACTS.md`](FACTS.md)에 **사이트에 실린 모든 수치의 출처**가 있습니다.
여기 없는 숫자는 쓰지 않습니다. 값을 고치려면 출처부터 갱신해야 하고,
표를 고치지 않고 코드의 숫자만 바꾸면 빌드가 실패합니다.

게이트는 커밋 시점에도 걸립니다. 어느 도구로 커밋하든 반드시 지나가는 층이기 때문입니다.

```bash
git config core.hooksPath .githooks   # 클론 후 한 번
```

## 구조

```
app/              라우트. 홈 + 케이스 상세 2개
components/
  home/           홈 섹션별 컴포넌트
  case/           케이스 본문 렌더러
    diagrams/     인라인 SVG 다이어그램
content/          카피 원본 (타입 붙은 데이터)
  cases/
types/            콘텐츠 스키마
lib/              메타데이터
public/
  fonts/          Pretendard · JetBrains Mono (self-host)
scripts/
  check-content.mjs   콘텐츠 게이트
  content-rules.json  검사 규칙
.githooks/
  pre-commit          커밋 시점 게이트
FACTS.md          확정 수치와 출처
CLAUDE.md         작업 규칙 — 톤·디자인 토큰·모션·품질 기준
```

`CLAUDE.md`는 AI 도구와 함께 작업하면서 **넘지 말아야 할 선**을 정의한 파일입니다.
확인되지 않은 주장을 싣지 않는다는 규칙, 색 사용 원칙, 카피 톤이 여기 있습니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
npm run build
npm run typecheck
npm run lint
npm run check      # 콘텐츠 게이트
```

**Node 20 이상**이 필요합니다.
